# Contributing to DEOS Open

DEOS Open gets better when the people who use it say what broke, what is missing and what worked. Thank you for helping.

## Three ways to help

| You want to… | Do this |
|---|---|
| **Report a mistake** (something wrong, unclear or out of date) | [Open a "Report a mistake" issue](https://github.com/letsbuild-math/cultmath-deos-open/issues/new?template=mistake.yml) |
| **Request a standard** that isn't here | [Open a "Request a standard" issue](https://github.com/letsbuild-math/cultmath-deos-open/issues/new?template=request.yml) |
| **Tell us how you used it** on real work | [Open an "I used it" issue](https://github.com/letsbuild-math/cultmath-deos-open/issues/new?template=used.yml) |

**Questions, ideas and show-and-tell** go in [Discussions](https://github.com/letsbuild-math/cultmath-deos-open/discussions).

**No GitHub account?** Use the form at [cultmath.com/deos](https://cultmath.com/deos#feedback). It goes to the same place.

## Suggesting an exact edit

1. Open an issue first, unless the change is a typo. It saves you writing a change that won't be merged.
2. Fork the repo, make the change on a branch, and open a pull request that links the issue.
3. Keep each pull request to one standard and one kind of change.
4. Follow the house style:
   - **Plain language.** Explain the mechanism instead of naming it. No jargon a reader wouldn't use.
   - **US English.**
   - **Every standard keeps its seven parts:** the one line, When to use, The standard, How to run it, Done when, Common failures, Template.
   - **Every figure has a source and a date.** If you can't source it, leave it out or label it a guess.
   - **No company, client or person is scored, ranked or criticized.**

## How changes are decided

- The maintainer, Ipalibo Da-Wariboko, reviews every issue and pull request and makes the final call.
- A change is accepted when it makes a standard clearer, more correct or more useful, without making it longer than the job needs.
- Accepted changes ship in a numbered release. The [changelog](CHANGELOG.md) lists what changed and credits who suggested it, by GitHub name or by first name if you used the form and asked to be credited.
- Some requests will be declined. The issue will say why.

## Licensing your contribution

By submitting a contribution, you agree that it is licensed the same way as the rest of the repository: **CC BY 4.0** for text and **MIT** for templates (see [LICENSE](LICENSE)). You confirm you have the right to contribute it, and that it contains nothing confidential from an employer or client.

## Be decent

Be specific, be kind, and argue with ideas rather than people. Reports and comments that are abusive will be removed.
