# W4 · Working Session That Decides

**Module:** Projects & People · **Version:** 1.0 · **From DEOS:** cm_90

> **A session with several parties exists to make decisions only those people together can make. Cut the agenda to those.**

## When to use

- A workshop, kickoff, planning session or cross-team meeting where three or more people each own a different part.

## The standard

1. **List every open question.** All of them, unfiltered.
2. **Run three tests on each:**

   | Test | The question | If it fails |
   |---|---|---|
   | **Exclusivity** | Can only these people, together, answer it? | Answer it alone or by email. |
   | **Blocking** | Is everything downstream stopped without it? | It can wait. Move it to Deferred. |
   | **Decidability** | Can it be decided now, with what the room knows? | It is a deferral in disguise. Get the missing information first. |

   Test 3 fails most often, and it is the costly one. A question nobody in the room can answer still eats its full time slot and still produces an answer, a bad one.
3. **What survives is the agenda.** Keep it short. Three to five decisions is a full session.
4. **Deferred list:** everything that failed, with an owner and a route.
5. **Send the agenda in advance,** framed as decisions: "Decide: which region launches first."
6. **End with a decision record** (C1) for each item decided.

## How to run it

1. Collect questions from every party.
2. Run the three tests.
3. Send the decision agenda and the deferred list.
4. Run the session. Record each decision as it is made.

## Done when

- Each agenda item has a decision record or a reason it was not decided.

## Common failures

- **Agendas of topics,** not decisions.
- **Questions nobody can answer yet** on the agenda.
- **No deferred list,** so people fight to get their items in.

## Template

```markdown
| Question | Exclusive? | Blocking? | Decidable now? | Agenda / Deferred | Owner |
|---|---|---|---|---|---|

**Agenda (decisions):** 1. 2. 3.
```
