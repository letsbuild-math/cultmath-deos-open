# P1 · Research to Product Loop

**Module:** Product & Innovation · **Version:** 1.0 · **From DEOS:** cm_94

> **Every lesson from research or users is extracted where it happens, qualified in a batch, and put into the product only after it is proven.**

## When to use

- You run research, user sessions or support, and want what you learn to actually change the product, the playbook or the template.

## The standard

Three parts:

1. **Extraction, at the source.** Capture the lesson when it happens, in one line: what was seen, where, and what it suggests. Do not wait for a monthly review; memory edits the lesson.
2. **Qualification, in a batch.** Each week or sprint, review the captured lessons. A lesson is promoted to a rule only when it recurs (for example, seen in three or more independent cases) or is backed by a costly signal (R6). One-offs stay in the log.
3. **Injection, one rule at a time.** Each promoted rule goes into the product, template or checklist as a separate change, so its effect can be seen.

**Guard rails:**

- **Check before shipping.** Rerun a fixed set of past cases with the new rule. If it breaks a case that used to work, it does not ship.
- **Prove before you announce.** No rule is described publicly until it has shown its effect.
- **Track the rejection rate.** If almost every lesson gets promoted, the bar is too low. If almost none do, you are not capturing enough.
- **User feedback used for improvement needs consent** where it could identify someone.

**The success test:** write down, in advance, a case the new rule should catch. Then check that it caught it.

## How to run it

1. Keep a lesson log open during every session.
2. Review weekly. Promote what recurs.
3. Ship one rule at a time, after replaying past cases.
4. Record each rule with the case it was meant to catch and whether it did.

## Done when

- Each promoted rule has its recurrence count, its replay result, and its pre-registered catch.

## Common failures

- **Lessons captured at month-end,** reshaped by memory.
- **Five rules shipped together,** so nobody knows which one helped.
- **A loud single user** turned into a rule.

## Template

```markdown
| Date | Lesson (one line) | Where seen | Recurrence | Promoted? | Rule | Replay passed | Expected catch | Caught? |
|---|---|---|---|---|---|---|---|---|
```
