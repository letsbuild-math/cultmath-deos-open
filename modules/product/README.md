# Product & Innovation

Turning research into product, testing with users, releasing safely, earning trust, auditing systems and setting hard limits.

| Standard | The one line |
|---|---|
| [P1 · Research to Product Loop](P01_research_to_product_loop.md) | Every lesson from research or users is extracted where it happens, qualified in a batch, and put into the product only after it is proven. |
| [P2 · Early User Sessions](P02_early_user_sessions.md) | Every beta or pilot session produces a written signal you can act on, or it was a demo. |
| [P3 · Release Checks](P03_release_checks.md) | Test the paths a customer actually takes, in order, before any customer takes them. |
| [P4 · Know the Product After Launch](P04_know_the_product_after_launch.md) | Build the maps that let you explain the product, see where it breaks, and decide what to improve next. |
| [P5 · Trust at Every Touch](P05_trust_at_every_touch.md) | Write down what would break your users' trust, and check every feature, message and price against it before it ships. |
| [P6 · Where Does the Knowledge Live?](P06_where_does_the_knowledge_live.md) | When a system has grown past what one person can hold in their head, audit where its knowledge lives, not whether it is good. |
| [P7 · Decide What It Will Never Do](P07_decide_what_it_will_never_do.md) | A system that survives has decided in advance what it will never do. A boundary that has to be remembered is not a boundary. |
| [P8 · A Playbook Has Been Run](P08_a_playbook_has_been_run.md) | A playbook that has never been run is a belief. The first run makes it a fact. And a playbook run perfectly can still lose money. |
