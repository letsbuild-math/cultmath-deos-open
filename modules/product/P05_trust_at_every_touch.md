# P5 · Trust at Every Touch

**Module:** Product & Innovation · **Version:** 1.0 · **From DEOS:** cm_21

> **Write down what would break your users' trust, and check every feature, message and price against it before it ships.**

## When to use

- Designing any product, feature, message, pricing page or data practice that users rely on.

## The standard

1. **Four kinds of trust threat:**
   - **Identity:** it makes the user feel replaced, judged or smaller.
   - **Authenticity:** the output feels generic, as if written for anyone with the name swapped.
   - **Privacy:** it asks for data the user cannot verify is safe or cannot control. For users who hold other people's data (agencies, advisors, clinicians), privacy runs two layers deep.
   - **Craft:** it feels like a shortcut to someone whose career is built on doing the work well.
2. **Keep a trust constraint register:** each constraint, the threat it addresses, and how you check it.
3. **The trust check, before anything ships.** Answer four questions:
   1. Could this have been written for anyone, with only the name changed?
   2. Does it suggest the product does the user's job, rather than supporting it?
   3. Does it require sharing data the user cannot verify is safe or cannot control?
   4. Would it feel like a shortcut to someone who built a career on doing this work?

   A yes to any is a trust violation. Fix it before shipping.
4. **Destructive actions** (delete, cancel, send to many) need a clear confirmation and, where possible, an undo.
5. **Say plainly how data is kept and used:** what, how long, who sees it, whether it trains anything.
6. **Pricing is a trust surface too:** no hidden fees, no confusing tiers, easy cancellation.

## How to run it

1. Write the register for your product.
2. Run the four-question check on each release, message and price change.
3. Log any yes and the fix.

## Done when

- Every shipped item passed the four questions, with any fixes logged.

## Common failures

- **"Our AI does it for you"** to an audience whose pride is in doing it.
- **Data practices explained only in the legal policy.**
- **Delete with no confirmation.**
