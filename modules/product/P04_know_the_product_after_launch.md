# P4 · Know the Product After Launch

**Module:** Product & Innovation · **Version:** 1.0

> **Build the maps that let you explain the product, see where it breaks, and decide what to improve next.**

## When to use

- After launch, when the product (or campaign, or service) is live and you need to understand how it actually works for people.
- Before a roadmap or budget conversation.

## The standard

Six lenses. Build only the ones the next decision needs.

1. **User journey emotion map:** each step a user takes, and how they feel at each one. Where are the low points?
2. **Iceberg:** what users see on the surface, and the systems, data and decisions underneath that produce it.
3. **Dependency web:** what depends on what. Which single failure takes down the most?
4. **Value chain:** where value is created and where it is captured, step by step.
5. **Competitive landscape:** what else the user could use, and where you are different. No scores for named competitors (R5).
6. **Living system map:** how the parts interact over time: loops that grow, loops that drain.

**Rules:**

- **Match the map to the audience.** The team needs dependency and iceberg maps; an executive needs the journey and value chain.
- **Maps are living documents.** Date them, and update them when the product changes.
- **One page each.** If it does not fit, it is two maps.

## How to run it

1. Name the decision.
2. Pick the one or two lenses that inform it.
3. Build each from real data: analytics, support tickets, user sessions (P2).
4. Use the map in the decision. File it with a date.

## Done when

- Each map is dated, sourced and used in a named decision.

## Common failures

- **Building all six** because they look good.
- **Maps drawn from memory** rather than data.
- **Never updated.**

## Template

```markdown
**Decision:** · **Lens(es):** · **Audience:** · **Date:** · **Data used:**
[map]
**What it changed:**
```
