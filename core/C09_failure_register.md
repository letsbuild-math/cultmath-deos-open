# C9 · Failure Register

**Module:** Core · **Version:** 1.0

> **Name the ways you usually fail before they happen, and log every time they do.**

## When to use

- Set it up once, at the start of a job or a business.
- Use it the moment something goes wrong in a way you have seen before, or might see again.

## The standard

1. **Write down your likely failure modes in advance.** Eight is a good number. Common ones for marketers and solo founders:

   | Mode | Early warning |
   |---|---|
   | Stall | The other side goes quiet; work sits unreviewed; no next step agreed. |
   | Conflicting advice | Two people you trust give opposite direction on a big call. |
   | Missed rhythm | Daily or weekly reviews skipped several times in a row. |
   | Deal reversal | A qualified buyer withdraws, goes cold or reverses. |
   | Scope creep | Work delivered beyond what was agreed, unnamed and unpriced. |
   | Build error | Something shipped broke, leaked or misled. |
   | Bad output | An AI or tool produced something wrong that nearly shipped, or did. |
   | Burnout | Tired after sleep, not before it. Busy without thinking clearly. |

2. **Every failure mode has the same protocol parts:**
   1. Definition: what it is, precisely.
   2. Early warning signs.
   3. First 24 hours: what to do the moment you recognize it.
   4. The path back, step by step.
   5. Escalation: the condition under which you bring in someone else, and who.
   6. Return condition: how you know it is over.
3. **Classify carefully.** Each log entry says why it is this mode and not a near neighbor.
4. **Log every instance.** Date, mode, what triggered it, what you did, whether you escalated, how it resolved, how long it took, what you learned.
5. **Fix the system, not just the case.** Each entry names the check or rule that now stops it recurring.

## How to run it

1. Write your eight modes and their early warnings.
2. Write a short protocol for each.
3. When one fires, open the protocol and follow it. Log it the same day.
4. Each month, read the log. Which mode recurs? Fix that one first.

## Done when

- The entry is logged within a day.
- It names the mode, why it is that mode, and the change that prevents a repeat.

## Common failures

- **Logging only big failures.** The small ones are the early warnings.
- **No return condition.** You never officially leave the failure state, so it lingers.
- **The learning is "be more careful."** That is not a fix. Name the check.

## Template

```markdown
| Date | Mode | Why this mode | Trigger | Actions | Escalated? | Resolution | Time to resolve | Learning / system change |
|---|---|---|---|---|---|---|---|---|
```
