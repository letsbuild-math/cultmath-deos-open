# C10 · Every Finding Comes With a Path

**Module:** Core · **Version:** 1.0 · **From DEOS:** cm_105

> **No honest read without a live path. No path the reader cannot walk.**

## When to use

- Any work that names a limit, a loss, a risk or a negative finding: an audit, a post-mortem, a competitive read, a "this won't work."

## The standard

1. **The path comes after the finding and cannot change it.** You may add a path. You may never soften, delay or reframe the finding to make room for one.
2. **A path passes four tests, or it is not a path:**

   | Test | The question | Fails when |
   |---|---|---|
   | **Named** | Is it one specific move? | "Diversify." "Get closer to the customer." |
   | **Available** | Can this reader start it with what they have? | It needs headcount, data or authority they do not have. |
   | **Costed** | Does it say what it costs: money, hours, or what is given up? | It is presented as free. |
   | **Testable** | Does it say what would show it is working, and by when? | "Over time you'll see results." |

   Three of four is false hope.
3. **The path is for the reader, not the subject.** A brand may be finished. The person reading about it still needs a move.
4. **"No path" is allowed, if you say why.** It must carry:
   - **Why not:** what specifically closes the path for this reader.
   - **The reopening condition:** the named change under which a path would exist. Never "things might improve."
5. **Banned:** "silver lining," "the good news is," "on the bright side," and "opportunity" used to rename a loss.

## How to run it

1. Write the finding. Lock it.
2. Draft one path.
3. Test it against Named, Available, Costed, Testable. Rewrite until all four pass.
4. If no path passes, write "No path," the reason, and the reopening condition.

## Done when

- The finding is unchanged.
- One path passes all four tests, or "No path" is written with its reason and reopening condition.

## Common failures

- **The cost is quietly left out.** A path without a cost reads like a sales pitch.
- **The finding gets softer as the path gets added.** Check the finding against its first draft.
- **A list of five paths.** Pick one. A list is a way of not choosing.

## Template

```markdown
**Finding:** [locked]

**The path:** [one move]
- Named: [ ]
- Available: [what the reader already has that lets them start]
- Costed: [money / hours / what is given up]
- Testable: [signal] by [date]

— or —

**No path.** Why not: [ ] · Reopens when: [ ]
```
