# Start Here

DEOS Open is 54 short standards. You do not need all of them. This page gets you running in a week.

## Day 1: set up the workspace

Copy the [`workspace/`](workspace/) folder into a place you own: a private repo, a shared drive folder, or a notes app. It has six folders:

| Folder | Holds | Standard |
|---|---|---|
| `decisions/` | One file per decision | C1 |
| `research/` | Briefs and findings | C3, Research module |
| `failures/` | The failure register and its log | C9 |
| `questions/` | The open question register | C8 |
| `reviews/` | Daily, weekly and monthly reviews | C12 |
| `published/` | Anything that left your hands: decks, memos, posts | C11, C13 |

## Week 1: run four Core standards

1. **C12 The Rhythm.** Close every day in five minutes. Do the weekly review on Friday.
2. **C1 Decision Record.** Write a record for every decision that matters this week.
3. **C3 Brief Written First.** Before any research or analysis, write the seven-field brief.
4. **C8 Open Question Register.** Log every question whose answer would change a decision.

That is the system. Everything else plugs into it.

## Then add the module for the job

Use [W1 Which Process](modules/projects/W01_which_process.md) to pick a standard for the moment you are in.

**Example: a category growth job.** You join a food company to grow a product line sold through distributors to restaurants and convenience stores. A sensible order:

| Weeks | Run | Why |
|---|---|---|
| 1–3 | R1 Map the Ground First · R2 Category Read | Know who decides, where the money sits and which dates are fixed before you recommend anything |
| 3–6 | R7 What Buyers Actually Said · R3 Category Entry Point Read | Learn the situations in which operators and end customers think of the category, in their words |
| 6–8 | M4 Value Position · M3 Working Backwards · M13 The Sell-In Story | Build the distributor, sales-rep and operator stories from the entry points and the four numbers |
| 8+ | R9 Can This Be Proven? · C4 Control · C13 Six-Lens Board | Set the bar and the baseline before launch, and take the recommendation to the decision-maker |

## Using it with an AI assistant

- Give the assistant the standard file at the start of the session, with your source material.
- Ask it to follow the standard's "How to run it" steps and fill in the template.
- Apply [W8 Working With AI](modules/projects/W08_working_with_ai.md): plan first, then verify everything it produced before you use it.

## How each standard is written

Every file has the same parts: **the one line**, **When to use**, **The standard** (the rules), **How to run it**, **Done when**, **Common failures** and a **Template** you can copy.

## Three rules under everything

1. Write the question down before you look at the evidence.
2. A missing signal is not good news.
3. Every judgment carries the thing that would prove it wrong.
